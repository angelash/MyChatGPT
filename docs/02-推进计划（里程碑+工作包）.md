## 0. 里程碑总览（建议顺序）

### M0：开工就绪（决策+环境）

- **输入**：`docs/00-执行准备与决策点.md` 已确认
- **输出**：虚拟声卡可用、端口放行、Windows/Android 环境 ready
- **验收**：Windows 本地能“抓系统声→写入虚拟声卡→浏览器能选到虚拟麦克风并录到声音”

### M1：协议合同落地（ABP/1.0）

- **输出**：二进制帧编解码 + 控制消息处理 + 测试向量
- **验收**：两端对同一向量“字节级一致”，丢包统计正确

### M2：Windows 音频 I/O MVP（无网络）

- **输出**：LoopbackCapture + VirtualMicRenderer + 基础日志/指标
- **验收**：能稳定抓/放 10 分钟不崩；设备变更能提示

### M3：Android 音频 I/O MVP（无网络）

- **输出**：MicCapture + SpeakerPlayback + 耳机提示
- **验收**：本地录/放无爆音、不卡顿

### M4：WS 传输层 v1（只跑控制+空音频）

- **输出**：hello/welcome + ping/pong + 单连接会话管理 + 重连
- **验收**：断网 10 秒自动恢复；5 分钟心跳稳定

### M5：端到端下行（Windows 系统声 → Android）

- **验收**：手机耳机能听到 Windows 浏览器声音，主观可用

### M6：端到端上行（Android 麦克风 → Windows 虚拟麦克风）

- **验收**：Windows 上虚拟麦克风电平变化明显；浏览器选择虚拟麦克风后能识别到讲话

### M8：省流优化（上下行）

- **输出**：codec 协商（`adpcm`/`pcm`）+ ADPCM 编解码 + 静音停发（DTX）+ bytes/丢弃帧统计
- **验收**：`codec=adpcm` 时单向 payload bytes 增长速度约为 PCM 的 ~1/4；静音 ≥200ms 时音频帧停发（仅保留心跳/控制消息）

### M7：稳定性与可观测性 + 一键诊断

- **输出**：指标面板、日志快照、测试音按钮
- **验收**：出现故障时能在 1 分钟内判断“是设备/网络/权限/配置哪个问题”

## 1. 工作包拆解（可直接作为 Issue）

> 你后续可以把每个 WP 变成一个 Issue，并把“验收标准”当作 done definition。

### WP0：仓库与合同先行（结构落盘）

- **内容**：创建 `/docs /proto /tests /src` 的基础结构（文档已先落）
- **你需要做**：无
- **验收**：仓库里有明确入口文档，任何模块都能按文档开工

### WP1：协议层实现（Windows + Android）

- **内容**：
  - `BinaryFrame` 编解码（严格按字节布局）
  - `SeqTracker` 丢包/乱序统计
  - `hello/welcome/ping/pong` 处理
- **依赖**：M0 决策（Codec、采样率等）
- **你需要做**：确认 codec 选项（`PCM16LE` / `ADPCM` / `Opus`，推荐 `ADPCM`）
- **验收**：
  - 测试向量通过（字节级一致）
  - 丢包统计与日志一致

### WP2：Windows 音频 I/O MVP（不联网）

- **内容**：
  - Loopback 抓系统声（固定到 pinned 输出设备）
  - 写入虚拟声卡 Playback
  - 10 秒录/放测试用例
- **依赖**：你已安装虚拟声卡；已确认设备名
- **你需要做**：
  - 安装虚拟声卡驱动
  - 在 Windows 声音设置确认设备存在
- **验收**：
  - 浏览器能用虚拟麦克风录到声音

- **验收**：
  - Start/Stop 连续点击 20 次不崩、不占死设备
  - 状态窗能看到关键指标刷新

### WP3：Android 音频 I/O MVP（不联网）

- **内容**：AudioRecord 采集、AudioTrack 播放、耳机提示
- **依赖**：Android 工程可运行
- **你需要做**：手机授权麦克风；最好准备耳机
- **验收**：录/放 10 秒均清晰，无明显爆音/卡顿

### WP4：传输层 v1（WebSocket）

- **内容**：WS server/client、会话管理、重连、心跳、收发二进制帧
- **依赖**：WP1（协议）完成
- **你需要做**：放行防火墙端口；确认手机能访问 PC IP

### WP5：端到端下行

- **内容**：Windows loopback → encode/pack → WS → Android decode → 播放
- **依赖**：WP2 + WP3 + WP4
- **你需要做**：戴耳机测试
- **验收**：手机耳机能听到 Windows 系统声，主观可用

### WP6：端到端上行

- **内容**：Android mic → encode/pack → WS → Windows decode → 写入虚拟声卡 Playback（支持 PTT）
- **依赖**：WP2 + WP3 + WP4
- **你需要做**：浏览器里把麦克风固定选到虚拟声卡 Recording
- **验收**：网页能识别到你讲话（至少触发“有声输入”）

### WP-OPT1：省流优化（ADPCM + DTX）

- **内容**：
  - codec 协商：`hello.cap.codec` 声明能力，`welcome.selected.codec` 下发选择（优先 `adpcm`）
  - IMA ADPCM：20ms 帧 `1920B → 484B`（约 4x 省流）
  - 静音停发（DTX）：静音连续一段时间后停止发送音频帧
  - 指标：上下行 payload bytes / 静音丢弃帧数可见
- **依赖**：WP4~WP6 任一链路已通
- **你需要做**：无
- **验收**：
  - 连接后能看到 `selected.codec=adpcm`（不支持则回退 `pcm`）
  - 持续有声时 bytes 增长速度约为 PCM 的 ~1/4
  - 静音 ≥200ms 时音频帧停发（仅保留心跳/控制消息）

### WP7：稳定性与可观测性

- **内容**：
  - 指标：丢包、JB 水位、underrun、设备重连次数

## 2. 风险点与提前规避

- **RDP 默认设备切换**
  - 规避：一律使用 pinned 设备；UI/日志提示当前默认设备变化
- **未戴耳机导致啸叫**
  - 规避：Android 端未检测耳机时强提示；默认禁用上行（可手动 override）
- **Android 录音权限/音频焦点**
  - 规避：首次启动就引导授权；播放/录音时正确申请音频焦点
- **流量高（PCM 常开）**
  - 规避：优先启用 `ADPCM（约 4x 省流）+ DTX（静音停发）`；若仍不足再考虑 Opus
